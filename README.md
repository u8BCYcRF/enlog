# Enlog

婚活を始める前後の準備、費用、日程、活動中の出来事を継続的に記録し、将来のnote記事へ加工するためのプロジェクトです。

単なる日記ではなく、これから結婚相談所を利用する人が、実際の費用感・準備期間・手順を具体的に想像できる一次記録を残すことを目的とします。

## 基本方針

- 構造化された事実と予定は `data/*.tsv` を正本とします。
- 本人の感想、判断、背景は `logs/activity.md` に分離します。
- 記事やまとめは正本から作る派生物とし、記事の都合で生データを書き換えません。
- 不明な日付・金額は推測せず、空欄または「未確定」として扱います。
- 日付は `YYYY-MM-DD`、金額は日本円で記録します。
- 第三者や本人を不必要に特定できる情報は記録・公開しません。

## データ構成

| パス | 役割 |
| --- | --- |
| `data/costs.tsv` | 支払実績、料金定義、予定、継続費、契約サービスの進捗 |
| `data/timeline.tsv` | 準備から契約、登録、活動開始、その後の主要イベント |
| `logs/activity.md` | TSVに入りきらない感想、判断、背景 |
| `articles/outline.md` | note記事へ展開するための仮アウトライン |
| `articles/note_draft.md` | 将来、TSVとログから執筆する記事本文の雛形 |
| `AGENTS.md` | Codexを含む作業者向けの更新ルール |

## 費用データ

`costs.tsv` の `category` は「結婚相談所」「婚活用衣類」などの用途を、`cost_scope` は集計上の扱いを表します。

| `cost_scope` | 日本語での意味 | 集計上の扱い |
| --- | --- | --- |
| `direct` | 婚活をしなければ基本的に発生しなかった直接費用 | 婚活直接費に含める |
| `self_investment` | 婚活終了後も本人に効果・利用価値が残る自己投資 | 直接費と分けて集計する |
| `excluded` | 婚活の有無にかかわらず発生する通常の日常費 | 婚活費から除外する |
| `recurring` | 月会費などの継続費 | 実際に請求された金額だけを月別に計上する |
| `progress` | 一括契約済みサービスの実施履歴 | 契約額を再計上せず、追加費用だけを計上する |
| `planned` | 未購入・未実施で金額も確定していない予定 | 実績合計に含めない |

`amount_jpy` はそのレコードで実際に集計へ加える金額です。料金の参考値は `unit_price_jpy`、補足は `note` に記録し、未確定の `amount_jpy` は空欄にします。

### TSVからの集計例

婚活直接費と請求済み継続費の合計は、次のようにTSVから計算します。

```bash
awk -F '\t' 'NR > 1 && ($8 == "direct" || $8 == "recurring") && $4 ~ /^[0-9]+$/ { total += $4 } END { printf "%d円\n", total }' data/costs.tsv
```

自己投資は直接費と混ぜず、次のように集計します。

```bash
awk -F '\t' 'NR > 1 && $8 == "self_investment" && $4 ~ /^[0-9]+$/ { total += $4 } END { printf "%d円\n", total }' data/costs.tsv
```

READMEには変化する合計額を大量に転記せず、必要な時点でTSVから再計算します。

## 更新方法

1. 新しい情報が「事実」「予定」「感想」のどれかを確認します。
2. 既存行に同じ支出やイベントがないか検索します。
3. 費用は `data/costs.tsv`、主要イベントは `data/timeline.tsv`、感想や背景は `logs/activity.md` を更新します。
4. 予定が実績になった場合は、重複行を作る前に既存行の `status` や金額を更新すべきか確認します。
5. 記事を更新する場合は、TSVの事実と矛盾していないか確認します。

詳細な判断ルールは `AGENTS.md` を参照してください。

## note記事にする際の方針

- 実費、実際にかかった日数、想定外だった点、やってよかったこと・不要だったことを、蓄積した記録から抽出します。
- 個人の実体験・感想と一般論を明確に分けます。
- ZWEIやIBJに関する一般情報には体験時点を明示し、公開時には公式情報の確認を検討します。
- 第三者を特定できる情報を除き、本人についても記事に不要な特定情報は一般化します。
- まだ経験していない出来事について、結論や教訓を作りません。
